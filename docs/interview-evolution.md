# V2 未来演进方案（面试说明）

本文记录当前 V2 选择轻量实现后的升级路径，描述的是后续设计，不代表当前版本已经接入。

## 1. SSE 断线恢复

当前使用 `runId` 状态查询恢复，避免断线后重复执行工具。若需要精确恢复到 token 位置，可将 SSE 事件写入 Redis Stream 或事件表，引入单调 `eventId`、`Last-Event-ID`、保留窗口和重放幂等。

## 2. 动态配置

当前使用本地 YAML 默认值加内存白名单快照，适合单机。多实例生产环境可迁移到 Nacos/Apollo，增加版本发布、灰度、回滚、权限审批和配置变更审计。

## 3. Token 与成本

当前按 provider/model 记录 usage，并使用可配置价格估算成本。后续可为每个 provider 接入官方或校准 tokenizer，价格迁移到带生效时间的数据库表，支持缓存 token、不同计费规则和历史重算。

## 4. API 幂等

当前对知识库创建、文档上传和评测任务支持 `Idempotency-Key` 或等价幂等键。后续可扩展到所有有副作用接口：以 owner、接口范围和参数指纹建立唯一约束，保存响应快照并设置过期清理任务。

## 5. 检索背压

当前检索线程池队列满时快速失败并返回 503。若业务更看重成功率，可增加串行降级分支；若流量继续增长，则应在网关层限流、按知识库设置配额，并通过压测数据校准线程池容量。

## 6. 提示注入防护

当前仅使用规则标记风险，不替代权限校验，也不自动拦截。后续可用脱敏攻击样本训练或选择分类模型，按风险等级执行告警、降级和人工审批，并持续评估误报/漏报。

## 7. Demo 与生产拓扑

当前 Compose 默认启动 PostgreSQL、Redis、MinIO；未启用 RocketMQ 时上传会复用同一条 Pipeline 同步入库，完整异步拓扑通过 `--profile full` 和 `RAG2AGENT_MQ_ENABLED=true` 启动。生产环境应补充独立配置、密钥管理、备份恢复、消息故障演练和 Jaeger/RocketMQ 父子链路验收。

## 面试回答主线

先用最小实现满足可靠性边界，再用指标和真实流量决定是否升级：状态查询解决 SSE 恢复，配置快照解决单机调参，provider 适配器解决模型差异，幂等记录解决网络重试，快速失败保护下游，规则标记建立安全基线，Compose profile 降低上手成本。每次升级都保留回退路径，避免为了“未来可能需要”提前引入高运维依赖。
